# 浏览器八项界面反馈修订

## 完成内容

| 反馈 | 修订 |
|---|---|
| 首页功能卡过于简单 | 改为四张分层功能卡，展示实际支持的归档、队列、复检、导出能力，补充格式及功能标签；没有新增精度或速度宣称。 |
| 首页团队大段文字 | 改为图片/标识、团队名称和三个方向标签；完整团队资料保留在联系页。 |
| 登录页不对齐且观感差 | 重做为同一容器中的等高双栏，左侧真实切面图、右侧表单；移动端保留紧凑表单。删除“1秒预测20张 / mIoU 63.4%”显示。 |
| 目录节点缩进空隙 | 隐藏独立拖动柄，缩减箭头和层级间距；根节点贴齐，操作按钮改为悬停显示，不再挤占文件夹名称。拖动和快捷操作保留。 |
| 图片排序工具框套框 | 去掉整组外框及下拉框重复边框，只保留轻量排序/分组和单层视图切换。 |
| 跨页全选含义不清 | 默认只显示“全选本页”；选满本页后再显示明确范围的全选入口，并显示已选数量及取消选择。 |
| 预测页介绍文字 | 去掉顶部介绍、四张总量卡和估算耗时。 |
| 预测页需下滑配置 | 开篇直接为左侧图片选择、右侧任务配置。目录搜索、图片搜索、排序、分页分区布局；配置区与图片列表独立滚动，创建按钮固定在配置底部。任务名就地填写，点击后直接创建，取消重复命名弹窗。 |

图片跨页和跨目录勾选保持，清空选择有明确入口；文件夹整批提交及冻结模型参数继续有效。另修正目录图片数重复累计和树组件隐藏测量节点引起的横向溢出。

## 验证

- TypeScript 检查、前端 **41 项**测试和 Vite 构建通过，未改后端推理和导入实现。
- 真实浏览器尺寸为 1864×884、1390×884、390×844；首页、登录、图片管理、预测共 12 组布局检查均无横向溢出。
- 桌面预测创建按钮底部为 y=867，低于视口底部 y=884，无需下滑页面。移动端为纵向布局。
- 桌面登录左右栏顶部同为 y=197.5，高度同为 584；手机尺寸单栏正常。
- 实测先选本页后出现“全选全部图片（2404张）”，取消选择后入口收起。
- 经新预测工作台直接创建任务 **105**，实际 CPU 预测完成，产生 1 条结果；命名弹窗不再出现。空任务名会阻止提交。
