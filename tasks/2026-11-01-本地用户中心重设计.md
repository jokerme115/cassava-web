# 本地用户中心重设计

## 范围与完成标准

用户要求在本地重做用户中心，明确个人设置与管理设置归属，修复角色和权限操作。交付标准为页面真实连通 API、授权变化立即生效、偏好保存后实际被复检和导出使用、桌面及手机可访问。不推送 GitHub，不部署云端。

## 已确认的问题

- RoleSerializer 未将 permission_ids 映射到 permissions，也未返回 user_count；前端回显为空、人数固定显示 0。
- 旧角色保存把权限差集传给后端“完整替换”接口，新增权限可能覆盖原有权限；多次请求无法保证整体成功。
- 普通授权管理员对角色、用户的操作被通用“所有者”判断阻止，这些管理对象并无 owner 字段。
- 权限按用户缓存一小时，角色和单独授权修改没有完整失效链路。
- 随意新建权限代码不代表功能接入；旧界面显示“未知权限”，没有解释授权入口。
- 通知开关未连接保存，双因素和全站暗色开关不可用；权限工作台与角色分配入口重复。
- 管理分页没有响应 page_size；旧操作日志同时手动和 effect 请求，pageSize 参数也与后端不一致。

## 本次实现

- 设置分为账号（资料、安全、工作区偏好）和管理（用户、角色、功能权限、站点、操作日志、访问统计）。按实际权限显示管理入口，使用 URL 查询参数保存分类。
- 扁平表格、统一字体层级与底部分页；编辑在侧边抽屉完成，移动端使用分类选择器。菜单入口统一叫“设置”。
- 角色可新建、编辑名称/说明/状态、完整选择权限、查看真实成员；仍有成员的角色禁止删除。
- 用户可创建、编辑、重置密码、停用、分配角色。界面不提供级联删除用户入口，避免误伤历史任务。
- 单独授权归入用户操作，每项明确为继承角色、单独允许、单独禁止。允许/禁止冲突和无效编号在保存前校验，事务保护完整写入。
- 角色权限通过一次事务请求保存；修复序列化映射。管理对象使用管理权限判断，图片与任务仍保留原所有者隔离。
- 权限目录只读，从实际 URL 路由视图声明判断是否绑定接口。未接入代码保留历史数据并标记、禁选，不再提供无实际功能的新建权限按钮。
- 取消一小时授权缓存，后端每次以当前授权为准；本地前端保存和重新聚焦时刷新授权。
- 增加工作区偏好 JSON 字段及 0044 数据库迁移。语言、复检主题、原图画笔直径、屏幕顶点大小、两层覆盖透明度、默认导出模板名称可保存到账号。
- 复检编辑器读取上述默认值；导出读取默认模板。模板内容沿用原先按账号隔离的本浏览器存储，在设置内明确可用范围。
- 移除未接通的通知与双因素开关，以及没有清理执行逻辑的保留期限配置；移除将分页误称为最大数据展示数量的设置。
- 操作日志合并为统一筛选表格，详情按需打开，支持正确分页；访问统计去掉重复容器，并补加载失败反馈。
- 资料与偏好先全部验证再事务保存，避免资料保存一半失败。限制普通用户管理者提升超级管理员、移除自己超级权限或停用自己。

## 使用方式与边界

1. 设置 → 角色 → 新建角色或“编辑与权限”，勾选可用功能并保存。
2. 设置 → 用户 → 编辑，选所属角色并保存。
3. 个别人需要例外，使用用户旁“单独授权”；默认继承角色，禁止覆盖允许。

权限代码由现有功能定义，不提供通过输入自定义代码生成新功能的假入口。超级管理员始终具有所有权限。工作区偏好在下次打开编辑器时作为默认值，当次工具调节不会自动改全局默认值。维护模式沿用原有工作区维护页，不将其描述为服务器 API 停机开关。

未执行线上推送或部署。原工作区已有大量未提交升级修改，本次保留并增量调整；旧组件内容备份于上述证据目录的 before 子目录，未删除用户文件。验收专用登录会话已单独注销，用户其他会话不受影响。INDEX 的 CAS-WEB 状态、下一步、最近更新已更新。

## 用户反馈后的视觉对齐

用户要求与前面工作区 UI 一致。本次仅修改 SettingsWorkspace 的结构和样式，保留所有业务逻辑。

- 移除独立硬编码颜色、字号与多余“设置”标题层，改用全站 design tokens；主色、字族、控件圆角与图片管理一致。
- 桌面侧栏改为 256px、深绿选中态，白色连续工作区；压缩页头与筛选间距。
- 管理表格使用同一白色底、浅色表头、柔和状态标签；数据区单独滚动，统一分页固定于底部。
- 个人设置采用左侧分区名、右侧字段的行对齐布局，缩短纵向空隙；手机回落为单列。
- 原生头像文件选择框强制隐藏，仅通过“更换头像”操作。
