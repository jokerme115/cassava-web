# 2026-10-23 UI 四点改造（横向滚动 / 结果编辑器 / 一屏化 / 配色与弹窗）

## 用户诉求（m03902 原文要点）

1. 图片管理右侧「所有图片」区域为什么会左右滑动；
2. 结果中心修改腐烂面积时要能编辑——掩码转成多边形、可拖动改范围；画笔/钢笔现在是十字星光标不方便勾选，钢笔的点很大，放大后难选；
3. 功能页面尽量一屏展示，减少上下滑动，特别是任务中心和修改部分；文字少、图标多、用 tooltip；
4. 弹窗与提示有多种，按具体任务合理选择，站在用户角度；
5. 全站颜色统一，参照导航栏的苹果玻璃质感黑白配色，不随意上色。

## 一、横向滚动（已完成）

- 定位：不是右侧图片区，而是左侧文件夹树。`ImageManagement.tsx` 左侧容器 `.flex-1.p-2.overflow-y-auto` 的 `scrollWidth 292 > clientWidth 255`（antd Tree 节点为 `min-width:auto` 不收缩），`overflow-x` 计算值为 `auto` 时可横拖。
- 修复：`ImageManagement.tsx` 左侧树容器加 `min-w-0 overflow-x-hidden`；右侧内容区同步加 `min-w-0 overflow-x-hidden` 兜底。
- 复测：1366 / 1440 / 1280 / 1024 / 900 / 768 / 390 全宽度 `document.documentElement.scrollWidth == clientWidth`，横向滚轮 `scrollLeft` 恒为 0。

## 二、结果编辑器（已完成）

文件：`网页/front/cassava_front/src/components/PredictionResultEditor.tsx`

- 新增 `traceMaskOutline()`（Moore 邻域 8 向边界跟踪）+ `simplifyPolygon()`（Douglas–Peucker）。新增工具栏按钮「掩码转多边形」：把当前图层掩码轮廓转成可编辑顶点（实测提示「已转换 3 个顶点」），自动切到钢笔工具。
- 顶点可拖动：`handlePointerDown` 先做顶点命中（`hitRadius = max(6*scale, width/220)`），命中则 `setPolygonDragIndex` 进入拖动，`pointermove` 更新该顶点，`pointerup` 结束。
- 顶点与线宽按屏幕像素换算（`scale = masks.width / canvas 显示宽度`），放大后顶点不变大、可点选。
- 光标：`crosshair` 改为按工具切换——画笔/钢笔时 `cursor: none`，改画叠加指示器：画笔为 `brushSize*zoom` 的白色圆环（最小 8px），钢笔为 2.5px 小白点，`pointerleave` 时隐藏。
- 一屏化：header 由三行（eyebrow + 标题 + 说明）压成一行（图标 + 图片名 + PPD 提示 tooltip）；「显示图层」四个开关由竖排改成 2×2 网格并配 title；右侧检查器整体收窄留白。

## 三、一屏化（已完成）

- 实测 1366×768：`/`、`/images`、`/prediction`、`/tasks`、`/results`、`/profile`、`/permissions`、`/audit`、`/contact`、`/no-such-page-xyz` 共 10 条路由，`scrollHeight == innerHeight == 768`，全部无竖向页面滚动、无横向溢出。

## 追加：掩码转多边形改为多环轮廓（2026-10-23 夜）

用户反馈「转多边形指的是把腐烂的边缘用多边形展示，这个功能目前不行」。复查后确认不是渲染问题，而是轮廓提取只做了单连通域。

根因：`traceMaskOutline` 从第一个非零像素出发、回到起点即停，只能拿到一个轮廓。而退出编辑器里这张图（`S98 (1).jpg`，4032×2268）腐烂掩码有 **88 个连通分量**，顶上是 13×15 的一个小碎片（43 点），经 Douglas–Peucker 简化后只剩 3 点 —— 所以点了按钮几乎看不到变化。

改造（`src/components/PredictionResultEditor.tsx`）：

- 新增 `traceMaskOutlines(mask, width, height, minArea)`：先 8 邻域 flood fill 打标签（`Int32Array` 标签图 + 每分量面积/包围盒），再对面积 ≥ `minArea` 的分量逐个做 Moore 邻域轮廓跟踪，返回 `PolygonRing[]`。
- 面积阈值 `minArea = max(24, round(width*height/60000))`；简化容差 `tolerance = max(2, width/480)`；单环不足 3 点直接丢弃。
- 新状态 `maskRings` / `maskRingDrag`，画布同时绘制多环虚线（青色 `#38bdf8` + 半透明填充）与每个环的全部可拖顶点；原钢笔多边形（琥珀色）逻辑保留。
- 新增「应用多边形（N 段）」与「放弃」按钮。应用时逐环按包围盒 + `pointInPolygon` 栅格化写回当前层掩码，随后 `commitSnapshot` + 更新指标，可 Ctrl+Z 撤销。
- 顶点拖动：`handlePointerDown` 先命中 `maskRings` 顶点（命中半径 `max(6*scale, width/220)`），命中即进入拖动；`handlePointerMove` 更新对应环顶点；`handlePointerUp` 复位。
- 清理逻辑（Esc、切换非钢笔工具、切版本、保存前校验、`hasPendingChanges`）全部纳入 `maskRings`。
- **关键修正**：转换后默认工具必须是 `pen-add`。此前按层设置 `pen-erase`，导致「应用」等于把病害擦掉，PPD 从 23.15% 掉到 4.06%。

实测（`网页/run_logs/qa-maskpoly-rings.mjs`、`qa-maskpoly-metrics.mjs`、`qa-maskpoly-drag.mjs`）：

- 点「掩码转多边形」→ toast「已转换 50 段病害边界（共 288 个顶点）」，耗时约 260ms，画布出现青色轮廓。
- 不改动直接应用：腐烂面积 97,917 → 101,525 px（+3.7%，来自轮廓经过边界像素的 1px 外扩），PPD 23.15% → 24.00%；撤销精确回到 97,917 px / 23.15%。
- 拖动一个真实顶点后再应用：腐烂面积 101,666 px、PPD 24.04%，与未拖动时不同，说明顶点拖动确实参与了栅格化。
