# 2026-10-24 全站 HeroUI 风格改造

## 背景与决策

用户 m06145 在三套视觉路线中选定 C（HeroUI 风格，柔和现代 Apple 派），m06286「可以的就按照这个修改」确认作为整站基线，取代此前的「iOS 玻璃 + 多彩渐变」。

改造原则：只改样式与少量文案，不动业务逻辑；不新增第三方依赖、不换 UI 框架（React 18 + TS + antd 5 + Tailwind 3.4 + Vite 5）。

## 踩坑记录

1. **PowerShell 改 TSX 模板字符串会写坏代码**：`-replace` / 双引号拼接会吃掉反引号与 `${}`，导致 ImageManagement.tsx 的三处计数徽标一度变成非法表达式（tsc 仍通过，因为 fragment 合法但渲染异常）。改 TSX 一律走 Node + `fs` + 正则。
2. **`AuthToken` 单会话**：后端每次登录会 `AuthToken.objects.filter(user=user).delete()`，任何并行登录都会让正在跑的浏览器 token 失效。截图/验证脚本必须只登录一次，且不要与手工 curl 登录同时跑（本轮出现过一次 `401 /api/auth/user/`，即此原因，非代码缺陷）。
3. 图片管理页仍有 48 个 `background-image: gradient` 元素，全部是图片卡 hover 遮罩（`from-black/70`），属正常交互层。
4. 批量替换遗留的非法类名如 `bg-white/40/70`、`bg-[rgba(...,0.16)]/90`（Tailwind 会忽略但不报错，表现为样式静默丢失），已全部清理。

顺手修掉的两个真实缺陷（截图复核时发现）：

1. **结果中心按任务过滤后可能整页空白**：`/results?task=59` 时任务存在但列表 0 条、指标全 0，同时侧栏还显示「5 条记录」。根因是链接参数是字符串、任务 id 是数字，`task.id === selectedTaskId` 恒为 false，页面同时被判为「任务无效」。修法：`ResultsCenter.tsx` 统一用 `String()` 比较（`activeTask`、`taskResults` 过滤、`taskCount`、侧栏选中态），并新增 `taskFilter`——任务确实不存在时才回落到全部结果，此时琥珀提示「没有找到这个任务」与实际展示一致。
2. **`useMemo` 依赖漏项**：过滤用的依赖仍是 `selectedTaskId`，改成 `taskFilter`。
