# 网页精度、人工校正与导出审查

日期：2026-10-18；对象：当前网页源码、现有本地 SQLite 数据与 5174 开发页面。

## 结论

当前首先需要修复结果真实性和任务参数传递，再评价或优化模型。已经确认“选择 M6 实际运行 ResNet-101”“真实零值被替换成演示值”两类问题；人工校正已具备像素级编辑、独立版本和后端重新计算，但最终图像、分段结果及导出尚未形成一致的交付结果。

本次没有修改业务代码，没有提交新预测任务或保存新校正版本。用户自行登录后，检查了结果中心、现有模型掩码及现有校正版本，触发了 CSV 导出按钮。导出出现成功提示，但尚未拿到浏览器下载文件做文件级验收，不能据此认定 CSV 已完成下载或 Excel 兼容性已通过。

## 检查证据与适用范围

- 只读查询数据库：31 条预测、7 条校正；模型预测中 22 条 PPD 为零。多个任务重复处理相同图片，因此这不是 31 张独立测试样本。
- 31 条模型预测的保存掩码均在本地存在，重新计算 PPD 与记录一致；7 条人工校正亦一致，没有发现像素除法或这批记录的存储数值错误。
- 3 条模型结果没有置信度图，相关智能点选功能不可用。
- 后端现有面积计算测试 4/4 通过；前端现有测量、单位与 CSV 转义测试 3/3 通过。这些测试不覆盖模型是否选对、人工编辑完整交互和大批量导出。
- 隔离调用源码函数进行参数、色彩通道和合成掩码检查；结果与可复跑脚本在 `tasks/2026-10-18-精度校正导出审查/`。
- 本次没有人工真值标签对照，无法给出当前网页版的实测准确率、病斑召回率或 PPD 平均绝对误差。

## 一、精度与结果真实性

### P0：零 PPD 被前端替换为演示值

证据：`网页/front/cassava_front/src/components/ResultsCenter.tsx:43-54`。

`effectivePpd` 在数值不大于零时，使用文件名和任务 ID 的哈希值生成 0.42%～3.47%，该数值参与列表、均值、最高最低值与分级。人工校正保存为 0% 时也会受影响；无效数值亦有被替换的风险。

实测：结果 ID 41、图片7.png，数据库及编辑器原始模型均为 0.00%，卡片显示 0.49%。同一图片在不同任务中会显示不同的非零值。

当前31条记录中，按“有校正采用最新校正、否则采用模型值”计算，真实均值为 **11.29%**；页面显示 **12.37%**。校正后仍为零的18条结果受到演示值替换影响。

修复方向：生产测量流程移除演示替换；零值、缺失、失败与单位未知分开表达。列表、编辑器、统计、分级及导出统一采用同一条测量规则。

### P0：模型选择及高级参数在执行任务时丢失

证据：

- `PredictionModule.tsx:206-216` 将模型名放在外层，将高级参数放入 `parameters`。
- `predict/services.py:3319` 执行时只读取 `task.parameters`，没有合并任务的 `single_model_type` 等外层字段。
- `predict/services.py:2711-2797` 解析器又优先按完整请求结构读取嵌套 `parameters`，与实际收到的扁平高级参数结构不一致。

数据库确认：任务28、32、34、35、36选择 M6，但相应 **14 条结果**记录为 ResNet-101；最近任务36的结果39、40、41均如此。另有历史任务真实记录为 M6，不能将所有历史 M6 结果统一判错。

隔离复现：传入扁平参数 `confidenceThreshold=0.91`、`minArea=7`、`patchSize=[256,256]`，解析后分别为默认的0.5、100、[512,512]。部分字段如 `stride` 恰好同名，可以被读取，不是所有参数都丢失。

另外，`use_post_processing`、`use_tta` 虽被解析，但 `run_predictions_for_images` → `integrated_prediction` 调用链未传递和采用这两个开关；预测函数仍固定执行后处理。

影响：页面上调参和比较模型可能没有作用；这些记录不能作为可靠的 M6/ResNet 精度对照。应修复后重跑指定样本，并保留原结果，明确标记旧任务的实际模型。

### P1：木薯总面积依赖颜色规则，且输入存在 RGB/BGR 混用

证据：`predict/services.py:1191-1193,1269-1380`；M6也调用该面积函数。

病变区域来自模型，但 PPD 分母的木薯范围由 HSV/Lab/YCrCb/RGB 阈值、形态学及轮廓填充产生。背景、尺子、反光、阴影和颜色相近的物体可能影响分母。

函数把 NumPy 三通道数组当作 BGR，但主要调用点传入由 PIL 转换的 RGB 数组；同一图以 PIL 和 NumPy 输入会得到不同的面积结果。对现有图片7原图的辅助调用，面积分别为109,323和84,091像素，差异25,256像素。此检查验证输入格式不一致，**不表示其中一个面积已达到人工真值，也不能直接套用为当前裁剪链路的 PPD 误差**。

合成检查：100×100的纯灰色图、没有木薯，也被识别为10,000像素木薯范围。需要统一色彩输入，建立主体分割或受约束的轮廓方法，并对空主体、异常面积、遮挡和漏切面设置明确失败状态。

### P1：后处理可能漏掉早期细病斑，也可能扩大环状区域

证据：`predict/m6_predictor.py:28-50`；旧模型的 `services.py:25-71` 使用相似逻辑。

默认去除小于100像素的连通域，再进行5×5闭运算、开运算和外轮廓填充。

合成检查：64像素小斑块与140像素细条处理后都变为0像素。独立检查外轮廓填充时，940像素圆环变成3,321像素。默认完整流程对同一圆环则变为304像素，说明不同形状可能被扩大或侵蚀，不能笼统认为后处理一定改善精度。

建议按图像分辨率与病斑尺度评估参数，分别报告病斑 Dice/IoU、早期病斑召回和 PPD 面积误差。不能仅凭叠加图更平滑来决定参数。

### P1：切面数量和异常状态缺少可靠约束

证据：`services.py:1014-1015` 按默认 `expected_count=3` 截断检测候选；`2990-3017`最多保存3份裁剪图和3份预测叠加图。

图片超过3个切面时，默认可能漏算；即使用户配置更多，图像交付仍只保留前3份。切面检测不足、部分子图推理失败，也可能继续生成成功结果：`1591-1633`跳过失败子图，`1696-1705`仍返回success。主体为空时亦返回零值，容易与真正健康的0%混淆。

建议提供“预期切面数/实际切面数/成功分析数”，让不完整结果进入待复核状态。

### P1：展示的90%和100%不构成精度证据

证据：`HomePage.tsx:27` 的识别一致性初值为90；`services/api.ts:226`与`useResultsStore.ts:39`将缺少的confidence设为1；后端序列化器不返回图像级confidence。详情因此可能把缺失信息显示为100%置信度。

M6 `metadata.json`保存的是fold1的`selection_metrics`，包括mIoU82.65%、病变类IoU68.41%、Accuracy97.07%。这些指标含义不同，该文件没有足够的独立测试清单和当前网页端到端评估证据，不能将其中任一数值当作当前网页准确率。

建议在修复链路后，对固定、按材料独立划分的带真值样本评估整个流程，覆盖轻微病斑、重度病变、不同背景、光照及切面数量，报告分割指标和PPD误差。

## 二、人工校正

### 已有可保留的基础

编辑器使用原分辨率二值掩码；木薯范围与病变范围分层编辑；后端将病变范围限制在木薯范围内并重算PPD；原模型结果保留，校正另存版本，记录操作者、时间和像素面积。7条现有记录复算一致。这部分无需推倒重做。

### P1：关闭、切换版本缺少未保存保护

证据：`PredictionResultEditor.tsx:729-743,875`。

关闭直接执行onClose；版本切换直接替换掩码并清空历史，没有dirty检查、离开提示或草稿恢复。钢笔尚未闭合和智能点选尚未应用时，保存只上传现有栅格，未完成的选择不会自动写入，容易误以为已保存。

建议加入未保存状态、完成或取消当前选择的提示、离开保护与草稿。当前审查只依据代码确认路径，没有丢弃用户的实际编辑内容。

### P1：校正后总值、分段值和图像没有同步

证据：`views.py:969-982`仅新增校正掩码与总PPD；`ResultsCenter.tsx:114-117,415-425`仍读取模型的vis_images与sub_ppd_values。

例如结果29从模型0%校正到12.92%，总值可以回显，但分段PPD、裁剪预测图及导出的预测图链接仍来自原模型。保留原模型结果是正确设计，但界面应明确区分“模型版”和“人工校正版”，并生成对应最终叠加图和分切面数值。

### P1：保存后可能跳到第一条结果

证据：`ResultsCenter.tsx:106-112,454-460`。

保存触发results:reload，新结果列表到达时effect无条件选择第一条；若当前编辑的不是第一条，编辑器可能切换到另一张图。此为代码路径确认，未向用户真实记录写入新版本来复现。

建议用结果ID保持当前选择，保存后只更新对应记录；同样要避免筛选变化时无提示换图。

### P2：智能点选依赖模型概率，无法替代人工判断

证据：`PredictionResultEditor.tsx:462-527`。

当前是对8位量化置信度图按相近概率做连通区域扩张，仅用于病变层，不结合图像纹理和真实边缘。当模型对病斑和正常组织都给出相近概率时，点选可能扩得过多或选不到想要的范围；3条现有结果缺少概率图。它适合作为辅助工具，不能承诺自动补回所有漏检。

### P2：版本追溯和大图操作仍欠完善

后端有版本、操作者和时间，但缺少前端备注输入、基于哪个版本编辑、复核通过/退回、明确指定最终采用版本。多人同时编辑时，最后保存的一版会自动成为最新结果，并不代表它已经审核。

保存掩码时存在分块异步处理，编辑工具仍可操作且没有完整快照隔离，应补测保存中继续绘制的情况。`commitSnapshot`在maxSnapshots=1时使用`slice(-0)`，会保留全部旧历史，超过约3,355万像素的大图可能突破64MB历史预算；需修复并补做大图内存与连续操作检查。

## 三、导出欠缺

证据核心：`src/hooks/useResultsStore.ts:12-52,94-147`、`services/api.ts:396-403`。

| 项目 | 当前行为 | 欠缺与建议 |
|---|---|---|
| 全量完整性 | 仅请求一页，导出当前内存results | 后端分页导出或遍历全部分页；显示应导出/已导出数量、缺失与失败项 |
| 最终结果 | 原模型PPD与人工PPD分列 | 增加最终采用PPD、来源、采用版本和是否已复核；保持与界面同一规则 |
| 校正图像 | CSV保留模型预测图和裁剪图链接 | 导出最终校正叠加图、木薯mask、病变mask；原模型与校正版分目录 |
| 分切面结果 | 子PPD以竖线拼到一个单元格 | 每个切面一行，记录切面ID、面积、PPD、位置与是否校正；总表明确面积加权口径 |
| 可追溯字段 | 缺少任务/结果ID、模型版本、参数、校正者等 | 增加样本ID、任务ID、结果ID、模型名和权重哈希、参数、时间、像素面积及审核状态 |
| 离线交付 | 多数资源仅为链接 | 提供ZIP包含真实图像、掩码、表格和清单；链接依赖服务器，OSS签名链接还可能失效 |
| 数据格式 | 仅CSV，中文英文表头混用 | 优先提供XLSX；CSV补明确编码/BOM兼容策略；PDF报告作为后续交付能力 |
| 错误反馈 | 点击下载后立即提示成功 | 区分文件生成和浏览器下载，生成失败可重试，空结果禁用导出 |

当前搜索和状态筛选会参与导出范围，这是已有正确行为；应把“导出当前筛选”“导出所选任务”“导出全部”明确区分。当前31条少于默认100条加载上限，未发生本次数据集漏导；分页问题是代码确认、待大批量场景验收。

已有CSV单元格转义和公式防护，相关测试通过。没有实测Excel打开，因此无BOM可能导致的兼容问题属于待验证风险，不能说所有中文CSV一定乱码。

另有单位兼容问题：API把ratio换算为百分数填入ppdValue，却保留ppd_unit=ratio；CSV直接把二者并列，会在未来ratio记录上输出错误的数值/单位组合。当前31条均为percent，本次数据不受这一分支影响。

## 建议研发顺序

1. **结果真实性**：移除零值替换，统一最终PPD与缺失/失败状态，消除默认100%置信度。
2. **预测链路**：统一任务参数协议，确认模型确实选对、高级参数确实生效；修正色彩输入，明确主体范围及切面完整性。
3. **人工校正闭环**：草稿与离开保护、保存后保持当前图片、校正总值与分段值及最终图同步，增加采用版本和复核状态。
4. **成果导出**：先完成全量XLSX/CSV与图像掩码ZIP，再做PDF报告；所有输出均追溯到同一个测量版本。
5. **精度实测**：固定一套带真值的独立样本，以相同输入和参数比较两模型；分别核验病斑分割、主体面积、最终PPD误差与人工校正耗时。

验收示例：0%保持0%；选择M6时执行记录、实际载入权重和结果标识一致；校正至0%后列表/统计/导出一致；切换图片不丢未保存内容；超过一页的数据无遗漏导出；离线ZIP可以重算出与表格一致的PPD。
