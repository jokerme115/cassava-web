## 1. 分支

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | 可运行、可部署的状态 | 只接受已验证的合并；不直接改 |
| `feat/<主题>` | 新功能或成批改造 | 如 `feat/design-token-v2`、`feat/owner-filter` |
| `fix/<主题>` | 缺陷修复 | 如 `fix/oss-auth`、`fix/task-validation` |
| `chore/<主题>` | 工程杂务（配置、依赖、脚本） | 如 `chore/nginx-align` |
| `exp/<主题>` | 可能被丢弃的实验 | 允许不合并 |

命名用小写连字符，主题写清「改什么」，不写日期（日期在提交里）。

## 2. 提交信息

格式：`<type>: <一句话结论>`

- `type ∈ feat / fix / chore / docs / test / refactor / perf`
- 主题行 ≤ 50 字，说结论不说过程；正文列关键改动与验证方式。
- 例：`fix: /api/oss/ 增加鉴权与归属校验（原 csrf_exempt 匿名可读删）`

## 3. 与批次计划的对应

`plans/2026-10-27-网页端体验收尾分批计划.md` 的每一批对应一个分支；批次 3（逐页对齐）按页面拆多个分支，一页一分支一提交，便于单页回滚。

## 4. 打入库 / 不入库

**入库**：源代码、配置模板（`.env.example`）、文档（`docs/ tasks/ plans/ notes/` 下的 md）、构建脚本、nginx/Docker 配置、截图证据（小体积）。

**不入库**（见根级 `.gitignore`）：`.env` 及任何真实密钥、`node_modules/`、`.venv-backend/`、`dist/`、`media/`、`*.pth`、`*.pt`、`*.npz`、`*.zip`、`*.sqlite3`、`网页/run_logs/`、`output/`、日志。

**大文件替代方案**：模型权重与导出数据用本地目录 + 文档记录相对路径，不进仓库；确需版本化的用 Git LFS（当前未启用）。

## 5. 备份策略变更

- 停用：`tasks/<日期>-*-backup-src/` 整目录拷贝。
- 改用：改动前 `git switch -c fix/xxx`，改动后提交；要对比旧实现用 `git show <commit>:<path>`。
- 例外：涉及非文本产物（如导出的 PSD/CSV）仍可放 `output/`，但该目录不入库。

## 6. 回滚

```powershell
git log --oneline                 # 找基线
git revert <commit>               # 已合并的改动，优先 revert 不 reset
git switch -c fix/rollback-xxx    # 需要保留现场时开新分支处理
```

已推送到远端后不改写历史（不用 `reset --hard` + 强推）。
