# 本地开发环境（2026-10-27 起）

> 目的：本机能起完整闭环，同时**不触碰生产资源**。
> 2026-10-27 之前 `.env` 只有一套（生产），本地跑后端会拿生产 PostgreSQL / OSS / 163 邮箱的密钥。

## 1. 三层设置

| 入口 | 用途 | 外部副作用 |
|---|---|---|
| `cassavaBack.settings` | 生产基线，读 `网页\back\cassavaBack\.env` | 真实：生产 PG、OSS、SMTP |
| `cassavaBack.dev_settings` | 本地开发 / 单元测试 | 全部归零：sqlite、console 邮件、本地磁盘存储、固定 dev SECRET_KEY |
| `cassavaBack.dev_runtime_settings` | 本地交互服务（要真跑预测） | 同 dev_settings，仅把 `PREDICTION_TASKS_DISABLED` 打开 |

`test_settings_sqlite.py` 与 `local_runtime_settings.py` 保留为兼容别名（历史脚本在用），新命令请用上表名字。

## 2. 起后端

```powershell
cd 网页\back\cassavaBack
$env:DJANGO_SETTINGS_MODULE='cassavaBack.dev_runtime_settings'
& 'C:\Users\Administrator\.conda\envs\hetao\python.exe' manage.py runserver 127.0.0.1:8000
```

- 数据库：本地 `db.sqlite3`（含 280 张图、35 条预测结果等真实样本）。
- 预测：`PREDICTION_TASKS_DISABLED=False`，任务会真的跑（CPU torch，单图约 10–20s）。
- 文件：落在 `网页\back\cassavaBack\media\`，由 runserver 直接服务 `/media/`。

## 3. 起前端

```powershell
cd 网页\front\cassava_front
npm run dev
```

- **必须用 `http://localhost:<端口>`（以 vite 输出为准，本次为 5173）**：vite 只监听 `::1`，`127.0.0.1:5174` 会连接被拒。
- `/api`、`/media` 由 `vite.config.ts` 反代到 `localhost:8000`。

## 4. 跑测试

```powershell
cd 网页\back\cassavaBack
& 'C:\Users\Administrator\.conda\envs\hetao\python.exe' manage.py test predict --settings=cassavaBack.dev_settings
```

当前基线：43 tests，约 3s，全绿。

## 5. 默认登录

- 用户名 `test` / 密码 `test`（超管，`db.sqlite3` 内 id=8）。
- 普通用户回归账号 `qa_normal2` / `normal123`（角色「普通用户」，仅存在于本地 sqlite）。
- 登录改为签发 `predict.LoginSession`：同一账号可同时保持多个会话（默认上限 5，`MAX_SESSIONS_PER_USER` 可覆盖），登出只吊销当前会话；前端仍把 token 存 `localStorage.authToken`，接口契约未变。
- 迁移 `0038_loginsession` 建表、`0039_purge_legacy_authtoken` 清空历史 DRF Token；升级后需重新登录一次。

## 6. 注意事项

- `dev_settings` 强制 `EMAIL_BACKEND=console`：注册验证码不会真发，直接看后端终端输出。
- `dev_settings` 清空 `OSS_ACCESS_KEY_ID/SECRET` 且 `FILE_STORAGE_BACKEND=local`：本地怎么传都不会进生产桶。
- 需要连生产库做只读核对时，**另起**一个临时设置模块，不要改这两个文件。
